# 卡牌信息 - 代价

卡牌的基础代价被标示在卡牌的左上角。

通用规则：

1. 代价要么是封存代价，要么是回忆代价；封存代价用黄色颜色代表，而回忆代价用蓝色颜色代表。

{% hint style="success" %}
卡牌的“代价”，当在其规则文本中被提及时，指的是该卡牌中体现的代价类别。一个英雄的回忆代价位于其印刷等级下方。
{% endhint %}

2. 如果该数字是一个封存代价，它代表必须从该玩家的手牌中面朝下放置进入[回忆区域](../../you-xi-ji-zhi/you-xi-ji-zhi-you-xi-qu-yu/you-xi-qu-yu-hui-yi.md)（也被认知为回忆）并直到下一次追忆被封存以作为该代价的支付项的卡牌数字。
   1. 在卡牌被选取用于支付封存代价的时点与那些卡牌被面朝下放置在回忆中的时点之间，没有时机被给予玩家，且不可采取玩家行动。

{% hint style="warning" %}
为了支付封存代价，从你的手牌中选取 X 张其他卡牌，其中 X 是启动所需卡牌要求的代价，并将它们面朝下放置进入你的回忆区域。
{% endhint %}

3. 如果该数字是回忆代价，该代价必须通过放逐从[回忆区域](../../you-xi-ji-zhi/you-xi-ji-zhi-you-xi-qu-yu/you-xi-qu-yu-hui-yi.md)中随机选取的卡牌来被支付。
   1. 为了支付回忆代价，从回忆区域中随机选取 X 张卡牌，其中 X 是想要具现的卡牌的回忆代价。
      1. 给定代价的非随机支付形式在随机代价被支付之前被支付。
   2. 在卡牌被选取用于支付回忆代价的时点与那些卡牌被放逐的时点之间，没有时机被给予玩家，且不可采取玩家行动。
4. 如果卡牌的启动或具现或启动能力有任何额外代价，它们必须在卡牌或效果进入效果堆叠之前，正常代价被支付的相同时点被支付。
5. 如果卡牌或效果作为卡牌结算的结果将指定一个代价，这些代价的支付遵循其中的规则文本和时点。

{% hint style="danger" %}
效果和能力可以修改被支付的代价。
{% endhint %}

4. 为了计算要求代价，相加任何修改效果应用的任何代价增加的数字数值，减去任何修改效果应用的任何代价减少的数字数值。该结果的数字是要求被支付的代价。
5. 代价的减免和增加通过分别削减或提升那个代价类别来改变卡牌的默认代价类别。对于主牌库卡牌的默认代价是封存代价，对于素材库卡牌的默认代价是回忆代价。
6. 代价不能被削减至 0 以下；如果一个代价将在数额上被削减到一个 0 以下的数字，改为该代价被设定为 0。
7. 如果一张卡牌具有由 X 代表的可变代价，X 的数值被视为当它被放置在效果堆叠上时作为 X 被选择的数字。
   1. 当卡牌不在效果堆叠上时，X 的数值被视为 0，除非当被考虑作为显式定义的卡牌集合（而不是隐式集合）的一部分时。见下方例子。
   2. 如果一张具有可变代价的卡牌被允许在不支付其封存或回忆代价的情况下被打出，X 必须被选择为 0；在这种情况下玩家不可为 X 选择任何其他数值。
   3. 对作为给定卡牌或物件效果一部分的 X 数值的引用将被视为该卡牌先前被选择的 X 数值。
   4. 如果一张在效果堆叠中具有可变代价的卡牌被复制，该被复制个体将承担原始卡牌选择的 X 数值。

{% hint style="warning" %}
例如，“代价小于 3 的卡牌”和“代价为 0、1 或 2 的卡牌”是不相同的，因为 X 的数值被考虑为 0 且属于隐含的集合，不属于 X 必须被显式提及的显式集合。这同样适用于搜寻或寻找一张代价为 0 的卡牌；这具体定义了 0 的代价而不是 0 或 X，因此仅受限于具有书面代价 0 的卡牌的选取。
{% endhint %}

8. 具有 X 代价的物件将被视为具有 0 代价。
   1. 如果一个效果复制一个在场上的物件，且其代价中具有任何 X 数值或 X 的先前设定数值，该复制的那些 X 数值被设定为 0 。
